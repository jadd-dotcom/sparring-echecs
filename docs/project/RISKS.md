# Risques

| N° | Risque | Constat (fichier) | Conséquence | Parade prévue | État |
|---|---|---|---|---|---|
| R-01 | Données uniquement sur l'appareil, effaçables par Safari | Toute la progression est dans IndexedDB (`src/db.ts:194-219`) ; aucun appel à `navigator.storage.persist()` dans `src/`. | Perte totale de la progression si le navigateur vide le stockage. | Exports réguliers par le propriétaire ; étudier la demande de stockage persistant. | Ouvert |
| R-02 | Import destructeur qui ignore le champ `version` | `importAll` vide les tables puis réécrit, sans lire `version` ni sauvegarder l'existant (`src/db.ts:244-258`) ; seule une confirmation `confirm()` protège (`src/screens/Settings.tsx:69`). | Un mauvais fichier ou un fichier d'un ancien schéma écrase les données actuelles. | Sauvegarde automatique avant import ; contrôle de `version` et migration. | Ouvert |
| R-03 | Progression dans des clés `meta` non typées | `interface Meta { key: string; value: unknown }` (`src/db.ts:176`) ; les clés sont des chaînes libres réparties dans les services (`src/*Service.ts`, `src/openings.ts`, `src/prefs.ts`…). | Renommer une clé ou changer une structure fait perdre la progression sans erreur visible. | Inventaire des clés ; règle « pas de changement sans migration testée » (`AGENTS.md`). | Ouvert |
| R-04 | Service worker en mise à jour automatique | `registerType: 'autoUpdate'` (`vite.config.ts:14`) ; `registerSW({ immediate: true })` (`src/main.tsx:7`). | Une version défectueuse publiée s'installe d'elle-même chez l'utilisateur. | Contrôles sur chaque PR ; test sur iPad avant validation ; retour au tag `v1.0-avant-refonte`. | Ouvert |
